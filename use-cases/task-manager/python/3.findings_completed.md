## 1. Executive Summary & Codebase Architecture

The Task Manager application is a zero-dependency Python CLI application implementing a clean **Layered Architecture**:

```
+-------------------------------------------------------+
|                    CLI Layer                          |
|                   (cli.py)                            |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|                 Controller/Service Layer              |
|                    (app.py)                           |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|                Data Storage / DAO Layer               |
|                   (storage.py)                        |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|                  Domain Model Layer                   |
|                   (models.py)                         |
+-------------------------------------------------------+
```

### Component Roles & Responsibilities
* **`models.py`**: Enforces domain entities (`Task`), enums (`TaskPriority`, `TaskStatus`), and entity rules (e.g. `is_overdue()`, `should_be_abandoned()`).
* **`storage.py`**: Manages JSON data serialization/deserialization (`TaskEncoder`, `TaskDecoder`), CRUD file operations, and CSV exports (`export_to_csv()`).
* **`app.py`**: Implements application-level controller service (`TaskManager`), handling business orchestration, statistics, and cleanup processing.
* **`cli.py`**: Argument parsing (`argparse`) layer exposing CLI commands (`create`, `list`, `status`, `priority`, `due`, `tag`, `untag`, `show`, `delete`, `stats`, `export`, `cleanup`).
* **`test_task_manager.py`**: Full unit testing suite for all models, storage operations, CSV export, and business logic.

### Part 3: Domain Model Understanding

#### Entity Relationship Diagram
```
+-------------------+          +-------------------+
|   TaskStorage     | 1      * |       Task        |
| (JSON Persistence)|--------->|  (Domain Entity)  |
+-------------------+          +-------------------+
                                         |
                              +----------+----------+
                              |                     |
                              v                     v
                     +-----------------+   +-----------------+
                     |  TaskPriority   |   |   TaskStatus    |
                     | (LOW/MED/HIGH/  |   | (TODO/IN_PROG/  |
                     |  URGENT)        |   | REVIEW/DONE/    |
                     +-----------------+   | ABANDONED)      |
                                           +-----------------+
```

#### Entity Breakdown & Attributes
* **`Task`**: Central entity representing a unit of work. Key properties include `id`, `title`, `description`, `priority`, `status`, `created_at`, `updated_at`, `due_date`, `completed_at`, `tags`.
* **`TaskPriority`**: Enum values `LOW` (1), `MEDIUM` (2), `HIGH` (3), `URGENT` (4).
* **`TaskStatus`**: Enum values `TODO` ("todo"), `IN_PROGRESS` ("in_progress"), `REVIEW` ("review"), `DONE` ("done"), `ABANDONED` ("abandoned").

### Part 4: Practical Scenario & Business Rule Implementation

#### Overdue Auto-Abandonment Rule
> *"Tasks overdue for more than 7 days should be automatically marked as abandoned unless they are high priority (`HIGH` or `URGENT`)."*

#### Code Implementation Summary
1. **`models.py`**:
   - Added `ABANDONED = "abandoned"` to `TaskStatus`.
   - Added `should_be_abandoned(days_overdue=7)` method to `Task` class. Exempts `HIGH` (3) and `URGENT` (4) priority tasks.
2. **`app.py`**:
   - Added `process_abandoned_tasks(days_overdue=7)` method on `TaskManager`.
3. **`cli.py`**:
   - Added `cleanup` command (`python -m python.cli cleanup -d 7`).
   - Added `abandoned` as valid status choice for listing and updating tasks.
4. **`test_task_manager.py`**:
   - Added unit test `test_overdue_and_auto_abandonment_rules` verifying that medium priority overdue tasks are abandoned while high priority overdue tasks remain protected.
